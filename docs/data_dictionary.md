# FlowPulse Platform Data Dictionary

This document details the schema, grain, storage types, business definitions, and lineage of all dimensional, fact, and analytical tables.

---

## 1. Dimensional Tables

### 1.1 `dim_users`
- **Grain**: One row per registered user.
- **Primary Key**: `user_id`

| Column Name | Data Type | Source / Lineage | Derived? | Description & Business Meaning |
|---|---|---|---|---|
| `user_id` | VARCHAR | `stg_users.user_id` | No | Unique identifier for registered user account (format: `USR_XXXXXX`). |
| `signup_timestamp` | TIMESTAMP | `stg_users.signup_timestamp` | No | Exact UTC timestamp when the user completed registration. |
| `signup_date` | DATE | `signup_timestamp` | Yes | Calendar date of user signup. |
| `signup_month` | DATE | `DATE_TRUNC('month', ...)` | Yes | First day of signup calendar month for monthly cohort assignments. |
| `country` | VARCHAR | `stg_users.country` | No | User IP-resolved country of origin (e.g. United States, Germany, India). |
| `acquisition_channel` | VARCHAR | `stg_users.acquisition_channel` | No | First-touch marketing channel (Organic Search, Paid Social, Direct, Referral, etc.). |
| `device_type` | VARCHAR | `stg_users.device_type` | No | Primary device classification used during registration (Desktop, Mobile, Tablet). |
| `browser` | VARCHAR | `stg_users.browser` | No | Browser client used at signup (Chrome, Safari, Edge, Firefox). |
| `initial_plan` | VARCHAR | `stg_users.initial_plan` | No | Subscription plan selected at signup (Free, Starter_Trial, Pro_Trial). |
| `current_plan_name` | VARCHAR | `int_user_lifecycle` | Yes | Most recent active subscription tier or initial plan if unpaying. |
| `is_activated_7d` | BOOLEAN | `int_user_lifecycle` | Yes | `TRUE` if user completed onboarding within 7 days of registration; `FALSE` otherwise. |
| `minutes_to_activation` | DOUBLE | `int_user_lifecycle` | Yes | Elapsed minutes from signup timestamp to onboarding completion. |
| `total_events_count` | INTEGER | `int_user_lifecycle` | Yes | Total lifecycle product events triggered by user. |
| `total_active_days` | INTEGER | `int_user_lifecycle` | Yes | Total distinct calendar dates on which user triggered at least one event. |
| `distinct_features_used`| INTEGER | `int_user_lifecycle` | Yes | Count of distinct core features engaged (0 to 5). |
| `total_sessions_count` | INTEGER | `int_user_lifecycle` | Yes | Total user sessions recorded. |
| `total_duration_seconds`| INTEGER | `int_user_lifecycle` | Yes | Total cumulative time spent in sessions (seconds). |
| `avg_session_duration_seconds` | DOUBLE | `int_user_lifecycle` | Yes | Average session length in seconds. |
| `total_purchases_count` | INTEGER | `int_user_lifecycle` | Yes | Count of paid subscription conversion orders. |
| `total_revenue_usd` | DOUBLE | `int_user_lifecycle` | Yes | Total cumulative gross revenue in USD generated by user. |
| `is_paying_customer` | BOOLEAN | `int_user_lifecycle` | Yes | Flag indicating whether user has converted to any paid tier (`total_revenue_usd > 0`). |
| `user_behavioral_segment` | VARCHAR | `int_user_lifecycle` | Yes | Behavioral tier: `Power User`, `Regular User`, `Casual User`, or `Unactivated`. |

---

### 1.2 `dim_date`
- **Grain**: One row per calendar date.
- **Primary Key**: `date_day`

| Column Name | Data Type | Source | Description |
|---|---|---|---|
| `date_day` | DATE | Calendar Generator | Full calendar date (`YYYY-MM-DD`). |
| `year_num` | INTEGER | `date_day` | 4-digit calendar year (e.g. 2026). |
| `quarter_num` | INTEGER | `date_day` | Calendar quarter (1, 2, 3, 4). |
| `month_num` | INTEGER | `date_day` | Calendar month index (1 to 12). |
| `month_name` | VARCHAR | `date_day` | Full month name (e.g. March). |
| `month_start_date`| DATE | `date_day` | First day of the calendar month. |
| `week_of_year` | INTEGER | `date_day` | ISO calendar week number (1 to 53). |
| `day_of_week_num`| INTEGER | `date_day` | ISO weekday index (1=Monday, 7=Sunday). |
| `day_of_week_name`| VARCHAR | `date_day` | Full day name (e.g. Tuesday). |
| `is_weekend` | BOOLEAN | `date_day` | `TRUE` if Saturday or Sunday, else `FALSE`. |

## 2. Fact Tables

### 2.1 `fct_events`
- **Grain**: One row per unique user interaction event.
- **Primary Key**: `event_id`
- **Foreign Keys**: `user_id` -> `dim_users.user_id`, `session_id` -> `fct_sessions.session_id`, `event_date` -> `dim_date.date_day`

| Column Name | Data Type | Derived? | Description |
|---|---|---|---|
| `event_id` | VARCHAR | No | Unique surrogate key for event (`EVT_XXXXXXXXX`). |
| `event_timestamp` | TIMESTAMP | No | Precise UTC timestamp of event execution. |
| `event_date` | DATE | Yes | Calendar date of event. |
| `user_id` | VARCHAR | No | User executing event. |
| `session_id` | VARCHAR | No | Associated browsing session ID (`SES_XXXXXXXX`). |
| `event_name` | VARCHAR | No | Event taxonomy identifier (`signup`, `onboarding_started`, `onboarding_completed`, `feature_used`, `intent_action`, `checkout_started`, `purchase`, `support_interaction`). |
| `feature_name` | VARCHAR | No | Sub-feature tag (e.g. `custom_dashboard_created`, `report_exported`, `slack_integrated`). |
| `page_path` | VARCHAR | No | Application URL path where event occurred. |
| `device_type` | VARCHAR | No | Client device category. |
| `country` | VARCHAR | No | IP country of origin. |
| `days_since_signup` | INTEGER | Yes | Whole days elapsed since the user's initial registration date. |

---

### 2.2 `fct_sessions`
- **Grain**: One row per user session.
- **Primary Key**: `session_id`
- **Foreign Keys**: `user_id` -> `dim_users.user_id`, `session_date` -> `dim_date.date_day`

| Column Name | Data Type | Derived? | Description |
|---|---|---|---|
| `session_id` | VARCHAR | No | Unique session identifier. |
| `user_id` | VARCHAR | No | Foreign key linking to `dim_users`. |
| `session_start` | TIMESTAMP | No | Start timestamp of first event in session. |
| `session_date` | DATE | Yes | Calendar date session commenced. |
| `session_end` | TIMESTAMP | No | End timestamp of terminal event in session. |
| `duration_seconds`| INTEGER | Yes | Session duration in seconds ($\ge 0$). |
| `duration_minutes`| DOUBLE | Yes | Session duration in minutes. |
| `event_count` | INTEGER | Yes | Number of distinct events fired within session. |
| `device_type` | VARCHAR | No | Client device type. |
| `country` | VARCHAR | No | Country location. |
| `had_conversion` | BOOLEAN | Yes | `TRUE` if paid purchase occurred in session. |
| `session_sequence_number` | INTEGER | Yes | Chronological session index per user (1, 2, 3...). |
| `is_first_session`| BOOLEAN | Yes | `TRUE` if session sequence number is 1. |
| `days_since_previous_session` | DOUBLE | Yes | Days elapsed since end of prior session via `LAG()`. |

---

### 2.3 `fct_conversions`
- **Grain**: One row per subscription transaction.
- **Primary Key**: `conversion_id`
- **Foreign Keys**: `user_id` -> `dim_users.user_id`, `conversion_date` -> `dim_date.date_day`

| Column Name | Data Type | Derived? | Description |
|---|---|---|---|
| `conversion_id` | VARCHAR | No | Unique transaction invoice identifier (`CNV_XXXXXX`). |
| `user_id` | VARCHAR | No | Converted customer user identifier. |
| `session_id` | VARCHAR | No | Session during which purchase completed. |
| `conversion_timestamp` | TIMESTAMP | No | Exact timestamp of transaction settlement. |
| `conversion_date`| DATE | Yes | Date of transaction. |
| `plan_name` | VARCHAR | No | Plan SKU purchased (`Starter_Monthly`, `Pro_Monthly`, `Starter_Annual`, `Pro_Annual`, `Enterprise`). |
| `billing_cycle` | VARCHAR | No | Billing frequency (`Monthly`, `Annual`, `Custom`). |
| `revenue_usd` | DOUBLE | No | Net transaction amount in USD ($29.00 - $1,999.00). |
| `days_to_conversion` | INTEGER | Yes | Days elapsed between user signup and purchase. |

---

### 2.4 `fct_experiments`
- **Grain**: One row per user experiment assignment.
- **Primary Key**: `assignment_id`
- **Foreign Keys**: `user_id` -> `dim_users.user_id`, `experiment_id` -> `dim_experiment.experiment_id`

| Column Name | Data Type | Derived? | Description |
|---|---|---|---|
| `assignment_id` | VARCHAR | No | Unique assignment identifier. |
| `experiment_id` | VARCHAR | No | Target experiment ID (`EXP-2026-01`, `EXP-2026-02`, `EXP-2026-03`). |
| `user_id` | VARCHAR | No | Assigned user identifier. |
| `variant` | VARCHAR | No | Assigned variant (`Control_...`, `Treatment_...`). |
| `assigned_timestamp` | TIMESTAMP | No | Timestamp user first entered experiment eligibility. |
| `assigned_date` | DATE | Yes | Date of assignment. |
| `pre_experiment_segment` | VARCHAR | No | Pre-treatment stratification tag (`device_type\|country`). |
| `is_activated_7d` | BOOLEAN | Yes | Binary outcome: activated within 7 days. |
| `has_converted` | BOOLEAN | Yes | Binary outcome: completed paid subscription. |
| `total_revenue_usd` | DOUBLE | Yes | Post-exposure revenue attributed to user. |
| `total_events_count`| INTEGER | Yes | Activity intensity after assignment. |
| `total_sessions_count`| INTEGER | Yes | Session frequency after assignment. |
| `had_support_ticket`| BOOLEAN | Yes | Guardrail flag: opened support ticket. |
